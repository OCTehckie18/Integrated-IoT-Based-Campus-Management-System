## 1. Manual test T5b - broker outage (not automated)
Needs an **administrator** PowerShell because it stops the Mosquitto service.
1. Start the classroom simulator (`python simulator/classroom_sim.py`) and open `http://localhost:1880/campus#module:classroom`.
2. `net stop mosquitto` -> expect: simulator prints `disconnected ... auto-reconnect running`; Node-RED MQTT node shows "disconnected"; dashboard keeps showing last data, health turns stale after the timeout.
3. Wait 20 s, then `net start mosquitto`.
4. Expect: simulator prints `connected`, Node-RED reconnects (no restart), readings resume within ~10 s, health returns to Online.
5. Record: time to recover, screenshot of the dashboard before/after, and whether any `device_offline` alert was raised then cleared.
Pass criterion: no manual restart of Node-RED or the simulator needed.

## 3. Safe power-up checklist (before any real hardware)
- [ ] Lab network only; not campus production Wi-Fi. No mains, distribution board or real pump anywhere.
- [ ] ESP32 powered from USB only; fan from its own low-voltage supply (<=12 V) through a transistor + flyback diode.
- [ ] Wiring checked against the pin map *with power off*; no GPIO driving a load directly; common ground between ESP32 and fan supply.
- [ ] PIR output voltage confirmed compatible with 3.3 V; DHT powered from 3.3 V.
- [ ] `secrets.h` exists and is gitignored; no Wi-Fi password in any committed file.
- [ ] Broker bound to localhost / lab interface; Node-RED bound to 127.0.0.1.
- [ ] Outputs default OFF at boot (firmware sets them LOW first).
- [ ] Serial Monitor open before the first power-up; check readings are plausible before enabling actuators.
- [ ] Nothing liquid near electronics; no smoke, gas or heat source used for the safety demo (push-button / scripted input only).

## 4. Demo script (about 4 minutes)
Setup before starting: Mosquitto service running, Node-RED running, `python simulator/campus_sim.py` **not** started yet. Browser on `http://localhost:1880/campus`, role Viewer. Delete `data/campus.db` first if you want a clean database (stop Node-RED first).

| Time | Do | Say |
|---|---|---|
| 0:00 | Show Campus overview | "Prototype of a campus IoT platform. My real module is classroom; everything is simulated and labelled SIMULATED. Other modules show 'No data yet'." |
| 0:20 | Run `python simulator/classroom_sim.py`, open Module page | "One MQTT message per metric, QoS 1, JSON contract. The page polls every 2 s." Point to units and 'updated x s ago'. |
| 0:50 | Type `enter`, `dark` in the simulator | "Occupied and dark: light turns ON." Show Light (LED) ON. |
| 1:20 | `temp 31.5` | "Above 30 C: fan ON, alert raised." Open Alerts tab. |
| 1:40 | Switch role to Viewer then Operator, Acknowledge | "Viewer can't acknowledge, operator can. Roles are simulated, not real security." |
| 2:00 | `temp 26`, then `dhtfail` | "Hysteresis: fan off below 27 C. Sensor failure: fail-safe off + critical alert." `dhtok` clears it. |
| 2:30 | Start `python simulator/campus_sim.py --demo` in a second terminal | "Optional simulator fills the other five modules, all labelled simulated." Show overview with 9 devices and alerts. |
| 3:15 | Admin tab: show rejected-message log; run `python simulator/send_one.py missing` | "Validation: missing field, unknown device, bad timestamp are rejected and logged." |
| 3:40 | Role Administrator, export CSV, apply a module filter first | "Filters and CSV export." |
| 3:55 | Ctrl+C the simulator | "Last will: broker marks the device offline, backend raises an alert." Close. |
